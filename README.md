# 📚 PDF RAG Assistant

An AI-powered **Retrieval-Augmented Generation (RAG)** application that allows users to upload their own PDF documents and ask questions about their contents. The application retrieves relevant information from the uploaded document and uses Google Gemini to generate clear, context-based answers.

Built using Python, Streamlit, LangChain, ChromaDB, Ollama, and Google Gemini.

## ✨ Features

- **Custom PDF Upload:** Upload a PDF of your choice through the Streamlit interface.
- **Question Answering:** Ask questions related to the uploaded document.
- **Retrieval-Augmented Generation:** Retrieves relevant document chunks before generating answers.
- **Semantic Search:** Uses vector embeddings and Maximum Marginal Relevance (MMR) retrieval.
- **Local Embeddings:** Uses Ollama's `nomic-embed-text` model to generate embeddings locally.
- **Persistent Vector Storage:** Stores document embeddings in ChromaDB for reuse.
- **Clean Responses:** Displays the generated answer without raw response metadata or signature information.
- **Source-Grounded Answers:** Instructs the model to answer using the retrieved context and admit when the document does not contain the answer.
- **Interactive Interface:** Provides a simple chat interface built with Streamlit.

## 🏗️ Architecture

The application follows a Retrieval-Augmented Generation workflow.

1. **Upload:** The user uploads a PDF through the Streamlit interface.
2. **Extract:** PyPDFLoader extracts text from the document.
3. **Chunk:** The extracted text is divided into smaller chunks with overlapping content.
4. **Embed:** Ollama converts the text chunks into vector embeddings.
5. **Store:** ChromaDB stores the chunks and their embeddings.
6. **Retrieve:** When the user asks a question, the retriever finds relevant chunks using MMR search.
7. **Generate:** The retrieved context and question are sent to Google Gemini.
8. **Display:** The application displays the generated answer in the chat interface.

## ⚙️ Prerequisites

Before running the application, install:

- Python 3.10 or a compatible version supported by the selected dependencies
- [Git](https://git-scm.com/)
- [Ollama](https://ollama.com/)
- A Google Gemini API key from [Google AI Studio](https://aistudio.google.com/)

## 🚀 Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/Venkat-Dev1/PDF-RAG-Assistant
cd your-repository
```

Replace `your-username` and `your-repository` with the values for your GitHub account and repository.

### 2. Create and activate a virtual environment

Create the environment:

```bash
python -m venv .venv
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

On Windows Command Prompt:

```bat
.venv\Scripts\activate.bat
```

On macOS or Linux:

```bash
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 4. Install the embedding model

Make sure Ollama is running, then execute:

```bash
ollama pull nomic-embed-text
```

The application uses this model locally to generate document embeddings.

### 5. Configure the Google API key

Copy `.env.example` to a file named `.env` in the project root directory, then add your API key:

```text
GOOGLE_API_KEY=your_google_api_key_here
```

Replace the placeholder value with your own valid API key.

**Security:** Never commit `.env` or expose your API key in screenshots, logs, or public repositories. The `.env.example` file is only a template.

### 6. Run the application

```bash
python -m streamlit run app.py
```

Open the local URL shown in the terminal, usually:

```text
http://localhost:8501
```

## 💬 How to Use

1. Open the PDF RAG Assistant in your browser.
2. Select a PDF using the upload control in the sidebar.
3. Click **Process PDF** and wait for processing to finish.
4. Enter a question in the chat input.
5. Read the answer generated using the retrieved document context.
6. Upload another PDF when you want to ask questions about a different document.

## 🔍 Retrieval Configuration

The application uses the following MMR retrieval settings:

```python
search_kwargs = {
    "k": 4,
    "fetch_k": 10,
    "lambda_mult": 0.5
}
```

- `k=4`: Returns up to four relevant chunks.
- `fetch_k=10`: Considers up to ten candidates before selecting the final results.
- `lambda_mult=0.5`: Balances relevance and diversity among retrieved chunks.

The document splitter uses a chunk size of 1000 characters and an overlap of 200 characters.

## 🔐 Security and Limitations

- API keys must be stored in environment variables and must never be committed to Git.
- Uploaded PDF files are processed by the application; use documents you have permission to process.
- Ollama must be installed and running on the machine hosting the application.
- Google Gemini requires network access and a valid API key.
- Scanned PDFs without extractable text may require OCR.
- Answers depend on the quality of the extracted text and retrieved context. Always verify important information against the original document.
- This project is designed as a local application. Deploying it publicly requires additional security, resource management, and user-isolation considerations.
